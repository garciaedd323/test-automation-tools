// TUTORIAL · JAVA + SELENIUM + GRADLE

Crea tu primera suite de
automatización desde cero

Un recorrido completo, paso a paso, para construir una suite real de tests con Selenium usando Gradle como gestor de build — desde la carpeta vacía hasta un pipeline de CI corriendo solo en cada push. Desplázate: el panel de la izquierda avanza como una ejecución real de pipeline.

STAGE 0

Prerrequisitos

Antes de levantar nada, confirma que el terreno esté listo.

terminal
java -version   # JDK 17+
gradle -version # opcional, usaremos el wrapper
Analogía — esto es como confirmar que tienes electricidad, agua y un terreno legalmente comprado antes de empezar a construir. Sin esto, ningún paso siguiente funciona bien.
STAGE 1

Crear el proyecto Gradle

Levantamos la estructura base del proyecto con el generador oficial de Gradle.

terminal
mkdir suite-login-tests && cd suite-login-tests

gradle init --type java-application --dsl groovy \
  --test-framework junit-jupiter \
  --package com.miempresa.automatizacion \
  --project-name suite-login-tests
estructura generada
suite-login-tests/
├── build.gradle
├── settings.gradle
├── gradlew           # wrapper — no requiere Gradle instalado
├── gradlew.bat
├── gradle/wrapper/
└── src/
    ├── main/java/com/miempresa/automatizacion/
    └── test/java/com/miempresa/automatizacion/
Analogía — el gradlew es como dejar una copia exacta de las herramientas de construcción guardada dentro de la propia obra: cualquier otro desarrollador usa la misma versión de Gradle sin instalarla manualmente. Evita el clásico "en mi máquina funciona".
STAGE 2

build.gradle — dependencias

La lista de materiales: Selenium, WebDriverManager y JUnit 5.

build.gradle
plugins { id 'java' }

java {
    toolchain { languageVersion = JavaLanguageVersion.of(17) }
}

repositories { mavenCentral() }

dependencies {
    // el motor que controla el navegador
    implementation 'org.seleniumhq.selenium:selenium-java:4.27.0'

    // descarga automática del driver correcto
    implementation 'io.github.bonigarcia:webdrivermanager:5.9.2'

    testImplementation platform('org.junit:junit-bom:5.11.3')
    testImplementation 'org.junit.jupiter:junit-jupiter'
}

test { useJUnitPlatform() }
Analogía — webdrivermanager es tu asistente que va a la ferretería y compra automáticamente la pieza exacta que necesitas según tu versión de Chrome instalada. useJUnitPlatform() es la línea que le dice a Gradle "usa JUnit 5 para correr esto" — sin ella, no sabría cómo ejecutar los tests.
STAGE 3

Primer test (crudo)

Sin estructura todavía — solo confirmar que la maquinaria enciende.

src/test/java/.../PrimerTest.java
public class PrimerTest {
    private WebDriver driver;

    @BeforeEach
    void setUp() {
        WebDriverManager.chromedriver().setup();
        driver = new ChromeDriver();
        driver.get("https://the-internet.herokuapp.com/login");
    }

    @Test
    void loginConCredencialesValidasFunciona() {
        driver.findElement(By.id("username")).sendKeys("tomsmith");
        driver.findElement(By.id("password")).sendKeys("SuperSecretPassword!");
        driver.findElement(By.cssSelector("button[type='submit']")).click();

        String mensaje = driver.findElement(By.cssSelector(".flash.success")).getText();
        assertTrue(mensaje.contains("You logged into a secure area"));
    }

    @AfterEach
    void tearDown() { if (driver != null) driver.quit(); }
}
terminal
./gradlew test
Analogía — esto es tu primera habitación funcional: sin decoración, sin planos guardados, pero ya sirve. El problema aparecerá cuando quieras construir 50 habitaciones parecidas a esta.

Esperas explícitas

Evitamos que el test sea flaky por timing de carga.

LoginTest.java
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));

wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("username")))
    .sendKeys("tomsmith");
// ...
String mensaje = wait.until(ExpectedConditions.visibilityOfElementLocated(
    By.cssSelector(".flash.success")
)).getText();
Analogía — instalamos un sensor de movimiento en la puerta en vez de asumir a ciegas que "seguro ya está abierta". Esto es puro Selenium — no depende para nada de Gradle.
STAGE 5

Refactor a Page Object Model

Contratamos a un "electricista especializado" por página.

src/main/java/.../pages/LoginPage.java
public class LoginPage extends BasePage {
    private final By campoUsuario = By.id("username");
    private final By campoClave = By.id("password");
    private final By botonIngresar = By.cssSelector("button[type='submit']");
    private final By mensajeResultado = By.cssSelector(".flash");

    public LoginPage(WebDriver driver) { super(driver); }

    public void navegar() {
        driver.get("https://the-internet.herokuapp.com/login");
    }

    public void login(String usuario, String clave) {
        escribir(campoUsuario, usuario);
        escribir(campoClave, clave);
        click(botonIngresar);
    }

    public String obtenerMensajeResultado() {
        return obtenerTexto(mensajeResultado);
    }
}
Nota de Gradle — LoginPage vive en src/main/java, no en test. Con el plugin java básico, el código de main es visible automáticamente desde test — sin configuración extra.
STAGE 6

Screenshots en fallos

La cámara de seguridad que solo se activa cuando salta la alarma.

utils/ScreenshotExtension.java
@Override
public void testFailed(ExtensionContext context, Throwable cause) {
    String nombre = "build/screenshots/FALLO_" + context.getDisplayName() + ".png";
    byte[] captura = ((TakesScreenshot) driver).getScreenshotAs(OutputType.BYTES);
    Files.createDirectories(Paths.get("build/screenshots"));
    Files.write(Paths.get(nombre), captura);
}
Diferencia clave con Maven — la carpeta de salida es build/, no target/. Es la convención de bodega propia de Gradle.
STAGE 7

Reportes con Allure

El plugin oficial de Gradle simplifica lo que en Maven requería un javaagent manual.

build.gradle
plugins {
    id 'java'
    id 'io.qameta.allure' version '2.12.0'
}

allure {
    version = '2.29.0'
    useJUnit5 { version = '2.29.0' }
}
terminal
./gradlew test
./gradlew allureServe
Analogía — es como si la ferretería te vendiera el kit de cámaras ya pre-armado, con los cables correctamente conectados de fábrica.
STAGE 8

Modo headless

En CI no hay pantalla — el navegador corre sin interfaz visual.

LoginTest.java
ChromeOptions opciones = new ChromeOptions();
if (System.getenv("CI") != null) {
    opciones.addArguments("--headless=new");
    opciones.addArguments("--no-sandbox");
    opciones.addArguments("--disable-dev-shm-usage");
}
driver = new ChromeDriver(opciones);
Analogía — es la fábrica funcionando sin luces para humanos: el trabajo se hace igual, más rápido, con menos recursos.
STAGE 9

GitHub Actions

Conectamos la casa a la red eléctrica de la ciudad.

.github/workflows/tests.yml
on:
  push: { branches: [main] }
  pull_request: { branches: [main] }

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { java-version: '17', distribution: 'temurin' }
      - run: chmod +x ./gradlew
      - run: ./gradlew test
      - if: failure()
        uses: actions/upload-artifact@v4
        with: { name: screenshots-de-fallo, path: build/screenshots/ }
Analogía — a partir de ahora, cada push activa a un "electricista automático en la nube" que revisa toda la casa sin que tengas que estar ahí físicamente.
